# ADR-009 — Push-to-talk with REST STT + keyterms for the MVP; streaming is re-evaluated in S2

> **Status:** Accepted
> **Baseline:** Revision 2, reviewed 6 Oct 2026; individual decision date not recorded
> **Origin:** Extracted from Architecture §21; existing ID and accepted meaning retained
> **Legacy references:** D14

## Context

Short Indian-English clips contain household names and brands; Android and iPhone record different native formats.

Saaras fits the 50-keyterm design, accepts both formats over REST, is India-hosted and supports codemix. Vendor accuracy claims are thin; household clips decide. Speechmatics lacks webm/opus, Voxtral lacks Tamil, Groq has consumer-term restrictions, AWS trains by default unless opted out, and Web Speech API lacks biasing and fails in iOS standalone. Detailed exclusions and challengers stay in the comparison.

## Decision

REST STT with native browser audio formats is the default; Sarvam Saaras v4 is the default (S2 compares ElevenLabs Scribe v2).

## Alternatives

streaming WebSocket STT; server-side transcoding.

## Consequences

simplest robust path for ≤ 30 s clips; S2 measures accuracy and latency on the shortlist; no transcoding binary is required.

Sarvam is an accepted baseline. S0 written household/minor-adjacent approval and retention/training settings are recorded green (Oct 2026). S2 compares Sarvam and ElevenLabs Scribe v2; native-format failures may use JS remux or drop the vendor. S2 supplies measurements; the consolidated roadmap assigns any streaming reassessment to Phase 6 if batch p95 warrants it. No ffmpeg is required.
