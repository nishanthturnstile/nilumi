# ADR-035 — Web Push, notification previews and delivery-stage measurement

> **Status:** Accepted
> **Baseline:** Revision 2, reviewed 6 Oct 2026; individual decision date not recorded
> **Origin:** Consolidated from the existing D/Q review and applied revision-2 requirements; no new product decision
> **Legacy references:** Q12

## Context

Reminders need a visible inbox fallback and honest delivery evidence because phone Focus modes, connectivity and OS policy affect presentation.

## Decision

Use standards-based VAPID Web Push with per-device subscriptions. Household reminders show text by default (configurable); private reminders use a generic lock-screen preview. Measure worker dispatch, push-service acceptance, service-worker receipt and user acknowledgement separately. Create an inbox item regardless of push outcome.

## Alternatives

OneSignal/FCM SDKs add lock-in for little benefit. Treating provider acceptance as phone delivery or promising alarm-grade presentation is rejected. Q12 retained household-text/private-generic previews.

## Consequences

Installed iOS Home Screen permission is required. Device health shows last acceptance/receipt and offers a test push; receipts are best effort. Revoke 404/410 subscriptions, retry other failures, and retain honest overdue/failure states. Notification-action scope stays in Product/Roadmap.

S1 proves real-device push. S5 and Phase 5 prove ≥ 200 occurrences dispatched within 60 s with no stale sends; those are dispatch gates, not phone-delivery guarantees.
