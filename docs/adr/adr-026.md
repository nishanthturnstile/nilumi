# ADR-026 — Family Records Vault (H1) with ID masking and MVP extension hooks

> **Status:** Accepted
> **Baseline:** Revision 2, reviewed 6 Oct 2026; individual decision date not recorded
> **Origin:** Extracted from Architecture §21; existing ID and accepted meaning retained
> **Legacy references:** D15

## Context

The family wants a historical knowledge repository covering medical, insurance, school and household documents after the MVP.

The comparison keeps hosted vision/OCR and a possible PaddleOCR service viable; no extractor is chosen yet. Append-only extraction preserves history. An approved extractor sees the original, while downstream retrieval and AI use masked identifiers; local OCR remains an alternative if no hosted processor passes.

## Decision

the Vault is H1, before the room speaker. The MVP reserves source/event/provenance hooks, shared detector `mask` mode, R2 key conventions and enum names; H1 adds document tables, extraction, masked chunks and citations. Delivery ownership is in the [roadmap](../core/05-implementation-roadmap.md#3-post-mvp-horizons-and-optional-backlog).

## Alternatives

keep documents/photos as a vague later import; build local OCR sidecar now; store only metadata.

## Consequences

the architecture grows toward a family memory platform without implementing the Vault in the MVP; hosted extraction processors must pass S0; ID numbers are masked before indexing, embeddings, Q&A prompts and display snippets.

MVP hooks do not implement the Vault. Extractor, original-view step-up policy and added cost remain H1 spike decisions; no approval or extraction benchmark is implied.
