# ADR-033 — Realtime invalidation and offline client-data boundaries

> **Status:** Accepted
> **Baseline:** Revision 2, reviewed 6 Oct 2026; individual decision date not recorded
> **Origin:** Consolidated from the existing D/Q review and applied revision-2 requirements; no new product decision
> **Legacy references:** D7, D9

## Context

Shopping must work on poor connectivity while private-memory revocation and member changes avoid persistent cross-account data.

## Decision

Use Postgres LISTEN/NOTIFY → `GET /v1/events` SSE to invalidate TanStack Query data, then refetch through normal Hono `/v1` APIs. Emit only IDs/kinds after a member RLS visibility check. Send heartbeat comments about every 25 s and reconnect with `Last-Event-ID`; invalidate on focus, reconnect and resume. Persist only lists, tasks and inbox in member-namespaced IndexedDB, wiping on logout/account switch. Memory stays online-only.

## Alternatives

Revision-1 polling-only primary sync is superseded. WebSockets are unnecessary for one-way invalidation. Zero/ElectricSQL/PowerSync add a sync server; Ably is a later option if SSE fails. Server Actions are not the domain-write path because future channels share `/v1`.

## Consequences

Offline mutations need durable member/request-hash receipts, canonical-ID remapping, monotonic tick-off and visible version conflicts. iOS has no Background Sync, so paused mutations flush on app open or connectivity recovery while open. Forget/un-share reaches the other phone through SSE, focus/reconnect refetch or next open; previously seen content cannot be recalled.

S1/S5 must prove stream/reconnect and cache hygiene. This consolidates D7/D9; it does not broaden the offline cache.
