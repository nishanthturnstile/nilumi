# ADR-043 — Durable runs on graphile-worker with leases and fencing

> **Status:** Accepted
> **Baseline:** October 8, 2026
> **Origin:** Owner-approved plan from the October 8 reference-architecture review, revised after an independent final review
> **Legacy references:** None
> **Supersedes / superseded by:** None. Extends [ADR-011](adr-011.md) and [ADR-004](adr-004.md)

## Context

A bounded agent run ([ADR-041](adr-041.md)) can wait for approval or input,
retry after a worker restart, or stop part-way through. graphile-worker
([ADR-011](adr-011.md)) provides jobs but not workflow replay.

The [reference repositories](../research/04-research.md#reference-repositories-claims-checked-8-oct-2026)
use:
- leases
- compare-and-swap transitions
- writer fencing (OpenClaw)
- an explicit "outcome unknown" error, with the warning that cancelling cannot recall a dispatched request (OpenMuse)

[DBOS Transact](../research/04-research.md#platform-constraints) is the closest
library alternative on Postgres.

## Decision

**Tables.** Run state lives in Postgres:
- `agent_runs`
- `run_steps`
- `tool_invocations` (already created before the pilot with approvals, [ADR-042](adr-042.md); the run migration adds its run foreign keys)- an append-only `run_events` table

graphile-worker jobs carry only a run ID.

**States.** `queued`, `running`, `waiting_for_input`, `waiting_for_approval`,
`paused`, `completed`, `failed`, `cancelled` and `outcome_unknown`. Only the
transitions in [Architecture §6.7](../core/02-architecture.md#67-durable-agent-runs)
are legal; the database rejects any other.

**Leases and fencing.**
- A worker claims a run with a lease TTL and renews it while working.
- Every write uses compare-and-swap on `(run_id, revision, writer_id)`. A stale writer is fenced out and cannot record steps or effects.
- Waiting states release the lease. A decision or input enqueues a new job.

**Effects.**
- An internal write and its receipt commit in one transaction, so its outcome is never unknown.
- An effect outside that transaction gets an idempotency key and an invocation record before dispatch. Examples are a push send now, or an external call later.
- If dispatch may have happened without a receipt, the invocation is marked `outcome_unknown` and is **never redispatched automatically**. The run waits for reconciliation or a person.

**Cancel and pause.** These stop future steps only. The UI states that an
effect already dispatched cannot be recalled.

**Budgets.** Every step reserves its maximum cost before the model call
([ADR-047](adr-047.md)).

**Scope and schedule.** The tables are defined before the pilot, but only
`daily_briefs` and `brief_items` from this family of tables are created then;
the Today brief is a deterministic cron job, not an agent run. The run tables
ship with the first bounded run type, after S-AGENT. Spike S-DBOS may compare
DBOS Transact before that.

## Alternatives

- **DBOS Transact.** A spike candidate: it offers durable workflow replay on Postgres but adds a programming model.
- **Temporal, Inngest, Trigger.dev and LangGraph checkpointers.** Rejected: each adds a service or another execution model.
- **Plain graphile-worker retries without run state.** Rejected: they could duplicate effects and cannot express waiting for approval.

## Consequences

Runs survive restarts without duplicate effects, and ambiguous outcomes are
visible rather than retried blindly. The cost is more schema, a transition
table and lease-expiry tests:
- a stale-writer fencing test
- a crash between dispatch and receipt
- cancellation after dispatch
