# ADR-014 — Forget = redact everywhere (with a documented backup window); undo = retract

> **Status:** Accepted
> **Baseline:** Revision 2, reviewed 6 Oct 2026; individual decision date not recorded
> **Origin:** Extracted from Architecture §21; existing ID and accepted meaning retained
> **Legacy references:** Original ADR only

## Context

Forget must remove source and derived content, while Undo must preserve recoverable history.

The backup review identifies a redaction/journal race: redaction, tombstone and outbox must commit together, and a backup must wait for the journal watermark. Restore replay prevents resurrecting forgotten data.

## Decision

forget scrubs every content copy, writes a transactional tombstone outbox, appends the R2 journal via worker and cannot be undone.

## Alternatives

soft delete only.

## Consequences

more complex forget code and audit jobs; real trust that "forget" means forget, subject to documented backup/provider limits.

Backups and provider copies have documented limits; [ADR-032](adr-032.md) governs encrypted recovery and retention windows.
