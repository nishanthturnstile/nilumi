# ADR-056 — Design system "Pastel Rooms" on shadcn/ui with Base UI primitives

> **Status:** Accepted
> **Baseline:** October 10, 2026
> **Origin:** Owner-led design-system discovery: six rendered directions compared, Pastel Rooms chosen; the plan, the token checkpoint and the finished build each reviewed independently by GPT-5.5, Claude Sonnet 5.5 and Gemini 3.8 Flash ([29 Appendix A](../design/29-design-system.md#appendix-a--review-and-resolutions))
> **Legacy references:** None
> **Supersedes / superseded by:** Refines [ADR-020](adr-020.md) and [Tech Stack §2](../core/03-tech-stack.md#2-client) ("Tailwind v4 + shadcn/ui") with the primitive base, icon set and motion scope

## Context

Phase 1 needs one approved visual language before any UI is built. The S1 spike has no visual identity. The PWA must feel native on an iPhone and an Android phone and stay excellent on desktop. It must be Tamil-ready and meet WCAG 2.2 AA with text up to 200%. The owner's brief: built for a mom and her children; spacious, colourful, a little playful, professional, not childish, and never a corporate SaaS dashboard.

October 2026 platform facts ([research](../research/30-ui-platform-research.md)) shaped the choice:
- shadcn/ui now supports Radix, Base UI and React Aria bases, and defaults to Base UI. Base UI ships a native-style Drawer (snap points, velocity-aware swipe, keyboard awareness) and a swipe-dismiss Toast; Vaul is near-dormant.
- OS text-size settings don't reach installed web apps.
- iOS 26 standalone apps have no back-swipe and colour the status bar from the page background.

## Decision

**Visual language: "Pastel Rooms"** ([29 Design System](../design/29-design-system.md)):
- Each tab is a room with its own pastel floor: Today peach, Lists mint, Talk lilac, Tasks butter, Memory sky, plus a linen room for Inbox, Settings, Admin and sign-in.
- White cards, navy ink, coral for Nilumi's voice.
- Rooms are wayfinding only; status uses semantic colours, and visibility (Household / Shared / Private) is shape-coded in ink tones.
- Dusky rooms in dark mode.

**Typography:** Nunito for all Latin text and Noto Sans Tamil for all Tamil, on fixed steps multiplied by an in-app text scale (100–200%) that changes type only.

**Tokens:** a single `packages/ui/src/styles/globals.css` in OKLCH.
- `data-room`, `.dark` and `data-text-scale` live on `<html>`, so portalled UI inherits them and the page background (the iOS status-bar colour) is the room floor.
- shadcn's variable names are kept; `--background` stays the white component surface.
- Tailwind's default palette is removed, so components can only use tokens.
- An automated contrast gate (`pnpm ui:contrast`) must pass for every room in both themes.

**Components:** shadcn/ui initialised on **Base UI** primitives, with the Maia style as a starting fork whose customised files are registered and re-diffed on update.

The pinned CLI encodes that choice as `"style": "base-maia"` in `components.json`,
not a separate `base` field. This corrects the configuration syntax without
changing the accepted primitive library or visual language.

**Icons:** Phosphor — regular, fill for active states, duotone for room icons.

**Motion:** CSS first; the Motion library only for gesture-driven pieces such as swipe rows.

**Package:** this existing pnpm monorepo and `packages/ui` (`@nilumi/ui`) hold the design system. Phase 1 adds `apps/web` and `apps/worker` here; `apps/web` consumes the existing UI package, whose `src/` gains reusable components as features need them. `specimen/` remains the review reference. There is no new application repository or replacement UI package; the spikes remain reference projects.

## Alternatives

- **The five other rendered directions** (Marigold Morning, Rangoli Colour, Moonlight, Paper & Stickers, Soft Native) and a first round of conceptual worlds. Not chosen by the owner: too complicated or SaaS-like (first round), or a weaker fit to the brief ([explorations](../design/explorations/2026-10-10-directions/index.html)).
- **shadcn/ui on Radix with Vaul.** Not chosen: Vaul's maintenance has stalled, and Base UI's Drawer is more capable.
- **Ionic React or Framework7.** Rejected: their own routers conflict with the App Router, and they bring non-Tailwind CSS.
- **Konsta UI.** Rejected: platform skins contradict one identity, and its accessibility is weak.
- **Tamagui, Mantine, Radix Themes, HeroUI as a base.** Rejected: compiler cost, desktop orientation, stale, or no bottom sheet.
- **Baloo Thambi 2 for Tamil headings.** Rejected: a display face that reads childish.
- **Scaling the root font size for large text.** Rejected: it inflates spacing and breaks layouts at 200%.

## Consequences

- Every component inherits tokens; colour, contrast and dark mode change in one file and are verified by the gate.
- The tab tray grows from 2 to 5 tabs by phase; the Talk tab navigates, and there is one mic per screen.
- Phase 1 must set `data-room`, the theme and the text scale before paint; update `theme-color` per room for Android; and keep `apple-mobile-web-app-status-bar-style` unset.
- Sheets need a history wrapper (Android back), and the Talk composer needs a `visualViewport` hook.
- Maia updates must be re-diffed against the customised-files register.
- **Pending validation:** the device QA matrix ([31 Device QA](../design/31-device-qa.md)) on both phones through the S1 `/design-check` route, covering the iOS 26 status-bar, viewport and overscroll interaction, keyboard, sheets and Tamil rendering offline.
