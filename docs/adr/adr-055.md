# ADR-055 — Application on `app.nilumi.in`, staging on `staging-app.nilumi.in`, marketing site on `nilumi.in`

> **Status:** Accepted
> **Baseline:** October 10, 2026
> **Origin:** Owner decision on application-flow open question OQ-4 ([28 Application Flows §9.2](../core/28-application-flows.md#92-resolved-questions))
> **Legacy references:** D4, Q8 (through ADR-016)
> **Supersedes / superseded by:** Amends [ADR-016](adr-016.md): the app's origin moves from the apex `nilumi.in` to `app.nilumi.in`; same-origin app, API and auth are kept

## Context

[ADR-016](adr-016.md) served the app, API and auth from `https://nilumi.in` and required the final origin before phones install the app, because installed PWAs, cookies, push subscriptions and WebAuthn bind to an origin. Phase 0 used a spike on `staging.nilumi.in`; no production app has been installed and the application workspaces have not been created yet. Phase 1 adds them to this existing monorepo and reuses `packages/ui` ([ADR-056](adr-056.md)). The owner wants a public marketing site on the apex domain. Google's OAuth consent screen also needs a homepage and privacy policy on an authorized domain before calendar linking ([ADR-045](adr-045.md)).

## Decision

| Origin | Purpose |
|---|---|
| `https://app.nilumi.in` | Production PWA, `/v1` API and auth routes, one origin. Family data lives only here |
| `https://staging-app.nilumi.in` | Staging deployment with its own database and credentials and synthetic data only |
| `https://nilumi.in` | Static marketing site: homepage and privacy policy. No sign-in and no app cookies |

- Same-origin app, API and auth from ADR-016 is kept, now on `app.nilumi.in`.
- Cookies are **host-only** (no `Domain` attribute), so the marketing site and staging never receive production session cookies.
- The WebAuthn relying-party ID is `app.nilumi.in`, so credentials are scoped to the app alone.
- Push subscriptions, the PWA install and the service worker bind to `app.nilumi.in`. Both phones install fresh from it, and each adult signs in once.
- Sign-in and invitation mail keep using the verified sender `no-reply@nilumi.in` (S6).
- Google OAuth: `nilumi.in` is the authorized domain; the homepage and privacy policy live on the marketing site; redirect URIs are on `app.nilumi.in`.
- The spike's `staging.nilumi.in` remains for spike work only and is retired for family use.

## Alternatives

- **Keep the app on the apex (ADR-016).** Rejected: the owner wants the apex for the public site.
- **Marketing site on a subdomain (`www`) and app on the apex.** Rejected: the owner prefers a clear `app.` origin, and nothing is installed yet, so moving now costs nothing.
- **Cookies on `.nilumi.in`.** Rejected: they would reach the marketing site and staging.

## Consequences

- DNS and TLS for `app.nilumi.in` and `staging-app.nilumi.in` are Phase 1 prerequisites, before either phone installs the app.
- The origin must not change again after installation without a planned reinstall and push re-subscription.
- The marketing site's hosting and privacy-policy content are an open question that blocks S-GCAL.
- Because the app moves to a new origin and database, the household acknowledgement is recorded again in the new app ([ADR-052](adr-052.md) requires explicit recording).
