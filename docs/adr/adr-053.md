# ADR-053 — Founding household bootstrap by an owner-only script, and invitation emails

> **Status:** Accepted
> **Baseline:** October 10, 2026
> **Origin:** Owner decision during application-flow planning before Phase 1 ([28 Application Flows](../core/28-application-flows.md#51-boot--household-bootstrap-and-member-administration))
> **Legacy references:** None
> **Supersedes / superseded by:** None. Extends [ADR-023](adr-023.md) and [ADR-048](adr-048.md)

## Context

Membership is invite-only ([ADR-023](adr-023.md)): an adult with the admin capability creates each profile and allowlists the email. That rule needs a starting point, because the first admin can't be created by an admin. [Architecture §15.5](../core/02-architecture.md#155-authentication-sessions-and-recovery) said only that the founding adult gets the capability "when the household is created". Contracts are ready for more households ([ADR-048](adr-048.md)), but only the founding household uses Nilumi before the legal and production privacy gates.

## Decision

- An **owner-only command-line script**, run with database access, creates the founding household (name, time zone `Asia/Kolkata`) and the founding adult with the admin capability.
- The script refuses to run when a household already exists and is not reachable over HTTP.
- There is **no in-app household setup** or sign-up screen. After bootstrap, an admin adds the other adult, children and their relationships in Admin → Members.
- The script does not record the household privacy acknowledgement. An adult records it in Settings → Privacy after the notice is explained ([ADR-046](adr-046.md), [ADR-052](adr-052.md)).
- **Invitation email (owner decision on OQ-5, October 10).** When an admin adds an adult, Nilumi sends an email from `no-reply@nilumi.in` with who invited them, a plain link to `https://app.nilumi.in` ([ADR-055](adr-055.md)), install steps for iPhone and Android, and an instruction to sign in with that email address. It contains **no sign-in link or token**; sign-in is still the in-app email code ([ADR-023](adr-023.md)). The admin can resend it until the adult first signs in; a failed send is shown in Admin → Members.

## Alternatives

- **One-time in-app setup wizard, locked after first use.** Rejected: it adds an unauthenticated or bootstrap-token surface to a single-household product, and its lock is another thing to get right.
- **Open sign-up for the first account.** Rejected: contradicts invite-only membership.

- **Telling the adult out of band only.** Rejected by the owner in favor of an invitation email.
- **Invitation link that signs the adult in.** Rejected: magic and invite links stay out of scope ([ADR-023](adr-023.md)).

## Consequences

- No public setup surface exists to attack or to leave open by mistake.
- Creating a second household later needs a deliberate new path, together with the legal gate ([ADR-048](adr-048.md)).
- The script is part of the Phase 1 deliverables and its run is recorded in the operations runbook.
- Resend also sends invitations: the invitee's email address, their display name and the inviter's display name. Invitation volume is negligible within the free tier.
