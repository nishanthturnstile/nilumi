# ADR-022 — LLM routing through the in-process AI SDK provider registry with model-role aliases; no hosted gateway

> **Status:** Accepted — partially superseded by [ADR-038](adr-038.md) (hosted AI Gateway for LLM/embeddings); registry aliases and fallback wrapper remain in force
> **Baseline:** Revision 2, reviewed 6 Oct 2026; individual decision date not recorded
> **Origin:** Extracted from Architecture §21; existing ID and accepted meaning retained
> **Legacy references:** D10

## Context

Provider experiments, fallback and model switching should require config and evaluation changes without adding another routing service.

Direct SDK calls preserve the household's own keys and terms. OpenRouter adds fees and a processor; Cloudflare adds a processor without a decisive advantage; LiteLLM and Bifrost add a service. Continuity concerns were recorded for Portkey, Helicone and TensorZero. AI Gateway was considered in revision 1 and dropped under revision 2.

## Decision

`packages/ai` exposes model-role aliases through `createProviderRegistry`/`customProvider`, pins exact model IDs in `config/models.ts`, applies `wrapLanguageModel` middleware for per-call defaults and uses a small fallback wrapper.

## Alternatives

hard-coded provider SDKs, OpenRouter, Cloudflare gateway products, LiteLLM/Portkey/Helicone/TensorZero.

## Consequences

switching provider/model is config + eval gate; no extra routing service, processor or fee; STT/TTS stay direct.

Fallback uses only approved challengers. A/B work is offline evaluation then minimized shadow traffic, with the pinned model serving answers; no live family traffic split.
