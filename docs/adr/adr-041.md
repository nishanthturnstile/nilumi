# ADR-041 — Two execution paths: constrained commands and bounded agent runs

> **Status:** Accepted
> **Baseline:** October 8, 2026
> **Origin:** Owner-approved plan from the October 8 reference-architecture review, revised after an independent final review
> **Legacy references:** None
> **Supersedes / superseded by:** Partially supersedes [ADR-003](adr-003.md): the fixed pipeline is no longer the only execution path. ADR-003's two-LLM-call ceiling and deterministic executors remain in force for constrained commands.

## Context

[ADR-003](adr-003.md) made a fixed sequence of AI SDK calls plus deterministic
executors the only turn pipeline. That remains right for commands such as "add
milk" or "remind me at 6". Some useful follow-through takes several steps, for
example turning a meal plan into list changes or preparing a renewal checklist
from stored facts. A fixed two-call pipeline cannot do these without growing
special cases.

The [October 8 review](../04-research.md#platform-constraints) found that
AI SDK v7 (S1 pins `ai` 7.0.130) provides:
- `ToolLoopAgent`, which defaults to `stopWhen: isStepCount(20)`
- `prepareStep`
- `activeTools`
- `toolApproval`

The [reference repositories](../04-research.md#reference-repositories-claims-checked-8-oct-2026)
bound such loops with server-side policy, approvals and durable state rather
than trusting the model. The daily Today brief does not need a loop; it is
assembled deterministically ([ADR-045](adr-045.md), [Architecture §13.4](../02-architecture.md#134-today-brief)).

## Decision

Nilumi has two execution paths over the same domain executors, RLS and receipts ([ADR-018](adr-018.md)).

1. **Constrained commands (default).** The existing turn pipeline:
   - At most two LLM calls.
   - Templated confirmations.
   - Undo-first writes ([ADR-010](adr-010.md)).
   - Every voice or text command takes this path unless a registered run type explicitly applies.
2. **Bounded agent runs.** Only for run types registered in code. Each run type declares:
   - an explicit `stopWhen: isStepCount(n)` (never the library default)
   - an `activeTools` allow-list, narrowed per step with `prepareStep`
   - a model role alias ([ADR-022](adr-022.md))
   - a maximum-cost reservation ([ADR-047](adr-047.md))
   - an eval suite

   Rules for every run:
   - Tools call the same executors through the tool broker and policy ([ADR-042](adr-042.md)).
   - Model output never authorizes an action.
   - Each run is durable ([ADR-043](adr-043.md)).
   - Results reach the client only as typed `nilumi-ui/1` parts ([ADR-044](adr-044.md)).

No agent framework is added; AI SDK remains the only model-orchestration
library. The general agent runtime, artifacts and delegation are post-pilot.
Before the pilot, Nilumi ships no bounded agent run. A run type ships only
after spike S-AGENT and its trajectory and approval-bypass evals pass. H7
conversation mode ([Architecture §20.6](../02-architecture.md#206-conversation-mode-horizon-h7)) is unchanged; it may later reuse
this path.

## Alternatives

- **Keep a single fixed pipeline.** Rejected: multi-step follow-through would need ad hoc special cases.
- **Adopt LangGraph, Mastra or the OpenAI Agents SDK.** Rejected for the reasons in ADR-003; they add an execution model and dependency surface the AI SDK loop controls do not require.
- **Use free-form tool calling for every turn.** Rejected: it gives up the correctness and latency guarantees of the command path.

## Consequences

The command path keeps its latency, testability and cost profile. Agent runs
add durable state, approvals, step budgets and new evals:
- trajectory with an allow-list check
- approval-bypass red-team cases
- privacy fixtures

Agent runs cost more per task, and their variable step counts must fit inside
the reservation. A run type that fails its evals stays disabled.
