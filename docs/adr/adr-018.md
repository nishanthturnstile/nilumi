# ADR-018 — Turn execution ledger with per-command receipts

> **Status:** Accepted
> **Baseline:** Revision 2, reviewed 6 Oct 2026; individual decision date not recorded
> **Origin:** Extracted from Architecture §21; existing ID and accepted meaning retained
> **Legacy references:** Original ADR only

## Context

A unique turn ID alone cannot show which commands committed before a crash in a multi-command turn.

The job/pipeline review keeps turn execution in a fixed sequence with a Postgres ledger instead of a workflow engine per turn. Durable receipts support honest result cards and replay.

## Decision

every command has a receipt and result card committed with its effect.

## Alternatives

a unique turn ID only.

## Consequences

crash-safe, resumable, replayable multi-command turns; requests bound to the member and a request hash; a little more schema (`turn_commands`, `mutation_receipts`).

Crash/retry and mixed-command success/failure checks remain Phase 1 requirements.
