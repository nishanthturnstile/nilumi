# ADR-044 — Artifacts and the trusted UI catalog `nilumi-ui/1`

> **Status:** Accepted
> **Baseline:** October 8, 2026
> **Origin:** Owner-approved plan from the October 8 reference-architecture review, revised after an independent final review
> **Legacy references:** None
> **Supersedes / superseded by:** None

## Context

The Today brief, approval cards and later agent results need richer output
than templated text. Model-generated markup would create an injection path into
the PWA. The [October 8 review](../research/04-research.md#platform-constraints) found
that A2UI (Apache-2.0, v0.9.1) uses a declarative catalog of pre-approved
components. That fits Nilumi's needs. AG-UI, CopilotKit and MCP Apps add
runtimes or protocols that are not needed yet. AI SDK `UIMessage` streams
already carry typed data parts.

## Decision

**Catalog.** Server output that is not plain text uses `nilumi-ui/1`, a
versioned catalog of Zod schemas in `packages/contracts`. It has eight
components:
- `card`
- `list`
- `form`
- `table`
- `progress`
- `approval`
- `artifact`
- `evidence-chip`

**Delivery.** Parts travel as typed data parts in AI SDK `UIMessage` streams,
or as typed REST payloads.

**Rendering.**
- The PWA renders only known components and props. Anything unknown falls back to plain text.
- No raw HTML is allowed, and markdown is rendered without HTML.
- The server composes components from validated data. Model text may fill text fields only and can never choose components or actions.

**Actions.** Component actions post to typed endpoints with a server-issued ID
(for example, an approval proposal ID). They never send executable arguments
([ADR-042](adr-042.md)).

**Artifacts.**
- Artifacts are versioned records (`artifacts`, `artifact_versions`) with an owner and visibility under [ADR-031](adr-031.md).
- RLS applies to them, and their `content_refs` support forget scrubbing.
- Any future sandboxed artifact needs a separate decision. The minimum bar is a `srcdoc` iframe sandbox without `allow-same-origin`, a strict CSP and no network access.

**Phasing.** Before the pilot, only `card`, `list`, `evidence-chip` and
`approval` are used, for the Today brief. Artifacts are post-pilot.

## Alternatives

- **Adopt A2UI as a dependency.** Deferred: its patterns are used, its packages are not.
- **AG-UI, CopilotKit or MCP Apps.** Deferred: they bring more runtime surface than one household needs.
- **Model-authored HTML or JSX.** Rejected as an injection risk.
- **Free-form markdown only.** Rejected: it cannot carry approvals or evidence links safely.

## Consequences

UI output can be tested against schemas. A new component needs a contract
change and a catalog version. Brief and approval cards can be snapshot-tested.
Artifact tables add RLS, forget and export work when they ship.
