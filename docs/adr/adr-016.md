# ADR-016 — Same-origin deployment on `nilumi.in`, bought before installing on the phones

> **Status:** Accepted
> **Baseline:** Revision 2, reviewed 6 Oct 2026; individual decision date not recorded
> **Origin:** Extracted from Architecture §21; existing ID and accepted meaning retained
> **Legacy references:** D4, Q8
> **Amended by:** [ADR-055](adr-055.md) (October 10, 2026): the app, API and auth move to `https://app.nilumi.in`; the apex hosts a static marketing site; staging is `https://staging-app.nilumi.in`. Same-origin and "final origin before installing" still apply.

## Context

Installed PWAs, cookies, push subscriptions and optional WebAuthn bind to an origin, so changing domains later disrupts both phones.

The dated RDAP/DNS research found nilumi.in likely unregistered, and the owner selected that domain only. Those findings are historical availability evidence, not proof of purchase.

## Decision

serve app, API and auth routes from `https://nilumi.in`; buy and attach the final domain before installing the PWA because installed origin, push subscriptions, Resend sender and optional WebAuthn step-up bind to it.

## Alternatives

separate static hosting + CORS; temporary platform domains; subdomain-first launch.

## Consequences

simple cookies and CSP; no CORS; domain setup is a Phase 0 prerequisite.

S6 purchase, TLS and sender verification precede S1 installation. Naming and the H2 wake phrase are recorded in [ADR-028](adr-028.md).
