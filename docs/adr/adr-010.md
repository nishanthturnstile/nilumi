# ADR-010 — Undo for requested reversible changes

> **Decision status:** Accepted current baseline, 2026-10-10.
> **Delivery status:** planned for MVP; P3–P6. Acceptance of a decision does not establish implemented or production-validated behavior.

## Context

The voice-first PWA uses one dynamic Home canvas and persistent activities. This record owns the undo for requested reversible changes choice within that experience.

## Decision

Execute requested reversible changes after deterministic validation, show the actual receipt and provide Undo. Clarify deterministic ambiguity rather than asking based on model confidence. Health/allergy facts require Confirm; forget requires irreversible confirmation; proactive suggestions require explicit proposal approval.

## Consequences and validation scope

Undo retracts the committed operation while preserving history. Barge-in stops speech, not a committed action. Approval and Undo are shared across touch, text and voice.
