# ADR-040 — Allow S3 synthetic-only evaluation on Vercel Gateway Hobby

> **Status:** Accepted
> **Baseline:** October 7, 2026
> **Origin:** Explicit owner approval: “Approve synthetic-only Hobby evaluation”
> **Supersedes / superseded by:** Scoped evaluation exception to ADR-038; family-data requirements unchanged

## Context

October 8 gateway amendment: the owner requested Cloudflare for synthetic
testing and subsequently clarified that either gateway may serve development
before a paid production route is selected. The same fixture-only exception and
cumulative cap apply. The owner subsequently funded Vercel credits and selected
Vercel for current testing. `NLU_GATEWAY` selects Vercel (default) or explicit
Cloudflare, without automatic fallback. Cloudflare has a separate unverified privacy
profile, managed-route configuration checks and conservative provider-specific
pricing. Vercel verification does not authorize Cloudflare. The legacy mode
name `synthetic_hobby` is retained on the wire; it is not a Cloudflare plan or
production approval. See [setup and acceptance blockers](../09-s3-cloudflare-gateway.md).

The authenticated [dashboard report](../08-s3-gateway-verification.md) shows
Hobby with US$5 remaining. Hobby cannot enforce provider ZDR, even per request,
or team provider/model restrictions. S3 already has 60 wholly synthetic cases.
The owner approved testing those fixtures under a cumulative US$0.50 cap,
while preserving the ZDR requirement for family data.

## Decision

October 8 funding follow-up: the owner purchased approximately USD 20 in Vercel
Gateway credits and authorized testing the frozen scenarios. Restore Vercel as
the default, retain Cloudflare as an explicit future spike adapter, and preserve
the cumulative USD 0.50 cap and all synthetic-only controls. See the
[paid validation report](../10-s3-paid-vercel-validation.md): Luna completed
60 cases but failed privacy/held-out gates; mini failed smoke and was stopped.
Paid access does not imply ZDR or production acceptance.

Add a separate `synthetic_hobby` mode to the staging evaluation route. Require
explicit exception approval, the fixed synthetic file hash, independent owner
review of expected actions, approved model IDs, inspected team metadata and
verified Gateway-managed OpenAI credentials. Requests contain only fixture IDs,
model IDs and pass count; arbitrary transcripts, audio and household data are
not accepted. A changed corpus fails even when its review hash is updated.

Every model call enforces no-training, OpenAI-only routing, `store: false` and
low reasoning, without tools, retries, fallback or repair. Provider ZDR is not
claimed in this mode. Unknown, BYOK or mismatched runtime routing stops further
calls. Reports label the exception and cannot establish production acceptance.

The server explicitly selects this mode. Default evaluation continues to
require ZDR. The runner retains its durable US$0.50 testing cap within the
shared US$5 monthly budget. Start with three Luna development cases; compare
Nano only within that same cap.

## Alternatives

Continue offline-only testing until ZDR is available; the owner instead chose
this limited synthetic exception. No paid Vercel plan change is authorized.

## Consequences

Synthetic model validation can proceed once the fixture review, credential
identity and staging gates are met. This cannot establish production privacy
or authorize family-data processing. Family LLM and embedding traffic remains
gated by ADR-038. No-training and `store: false` do not mean zero retention.

## October 7 follow-up — subscription prompt development

The owner approved the proposed subscription-only synthetic correctness plan
with “pls proceed”. Use the already authenticated ChatGPT/Codex client locally
to evaluate `gpt-6-luna` at low reasoning. This is a development workflow;
it does not add a subscription provider to the hosted application or change
the Gateway candidate list, privacy controls, deadline or spending cap.

The local runner accepts only cases from the same frozen reviewed corpus,
defaults to its 48 development cases, and requires a frozen prompt hash before
held-out evaluation. Each extraction uses a fresh ephemeral session in a
temporary directory containing only the schema and parser instructions.
Expected answers stay in the parent scorer. User/project instructions, hooks,
plugins, memories, shell and browser tools are disabled; detected tool activity
or execution errors stop new dispatch. API credential environment variables
are removed, ChatGPT login is required, and no API/Gateway fallback is allowed.
Up to two independent requests may run together. The runner does not retry;
the built-in Codex transport behavior remains outside the runner's control.

Use unchanged contracts, validation, golden answers and correctness thresholds.
Tune only against development cases; freeze the prompt before the 60-case pass.
Keep subscription reports separate from the Gateway ledger and label costs
unknown under the subscription allowance. Codex process timing is not evidence
for the deployed five-second deadline or 1,400 ms p95 target. Subscription
privacy settings apply; neither Gateway no-training verification nor ZDR is
established by these runs. No family data is authorized.

## October 7 follow-up — deterministic interpretation

The owner requested research, implementation and validation of the next
correctness work, and a check-in of existing changes. Keep the original
approved corpus and acceptance thresholds. Use a deterministic application
stage between extraction and validation to resolve supported literal date
phrases against `occurred_at` in Asia/Kolkata. This stage cannot invent a
missing phrase or time, select a different record, or make another model call.
It preserves ambiguous and unsupported inputs for the existing validator.
Both date-valued fields and their duplicate ISO values use the same calculation.

Retain raw extraction scores separately from interpreted pipeline scores and
record every date normalization. Reference consistency is improved through
development-only prompt instructions. Unique visible note references for share
and unshare are canonicalized to their existing memory ID only when all supplied
selectors agree. Hidden, ambiguous, conflicting or invented IDs are not repaired;
ownership checks still reject sharing another person's note. Missing member IDs
are filled only from a unique visible alias for reminder/task references; supplied
conflicting IDs and ambiguous aliases remain unchanged. An omitted adjacent
explicit clock invalidates the interpreted command rather than scheduling a
daypart default in its place.
Freeze the complete pipeline fingerprint as well as the prompt before a full
benchmark. A repeated run of the original holdout is a regression result:
prior aggregate metrics and failed case IDs were seen, but held-out transcripts
and expected answers were not used for this revision. Do not call this a new
independently authored holdout. Gateway model selection and family-data use
remain subject to their existing live and privacy gates.

Live follow-up observed collaboration tool events even with both installed CLI
multi-agent feature switches explicitly disabled. Those results are rejected and
remain failures in the benchmark; the runner's configuration alone does not prove
tool-free isolation. Resolve this limitation before treating subscription runs as
acceptance evidence. Do not permit tool outputs or hide failed requests to make
the comparison pass.

## October 8 follow-up — explicit collaboration disable and streaming guard

The owner authorized research, implementation and validation of the remaining
subscription correctness item. The official Codex configuration schema defines
`agents.enabled` separately from the legacy feature switches. Set it to false
for the evaluator, retain both disabled feature switches, exclude collaboration
and clock from nested code mode, and require strict CLI configuration parsing.
Do not change the owner's persistent Codex settings or login.

Inspect JSONL during execution; stop on the first observed tool or error event,
reject the output and stop new dispatch. Bound event and stderr buffers. Keep
post-turn completeness checks and frozen source fingerprints. Observation can
follow dispatch: this guard does not establish that a tool never started, and
the CLI harness cannot be equated with a direct `tools: []` model request.
Record configured controls and observed activity separately in every report.

Prompt v8 distinguishes extraction from execution policy. A supported sharing
request still emits its visible target for ownership validation, even when the
speaker does not own it. Ambiguous supported actions retain selectors/missing
slots for clarification. Strengthen literal shopping and memory extraction
using development evidence; preserve all contracts, thresholds and goldens.
The full original holdout remains regression evidence, not a new independent
acceptance sample. No held-out transcript, answer or raw output is used to tune.

## October 8 follow-up — small-model extraction prompt

The owner approved v9 prompt development after the managed Nano smoke failed
ordinary-preference intent. Consolidate instructions, separate current_input
from the full visible reference_context, and add independently authored
preference/correction contrast examples. Preserve original context content,
visibility filtering and sensitive-input scanning, parser contracts, scorer,
goldens, interpreter and hosted model settings. Do not rewrite a model's
incorrect command intent deterministically to obtain a passing score.

Validate examples with the existing validator and test the unsupported
correction rejection. Tune only with development evidence; freeze prompt and
pipeline before the original-corpus regression. Prior holdout score/ID exposure
remains disclosed. A passing subscription run is a gate to an authorized hosted
smoke, not model selection. Recheck rates and retained budget before live calls;
stop after a failed smoke and verify evaluator shutdown.

The frozen v9 regression failed held-out, date and privacy gates. This prompt
remains an unaccepted local candidate; it does not replace the disabled staging
artifact or authorize hosted calls before a qualifying synthetic revision.

V10 preserves ambiguous clock phrases and suppresses inferred types, with
explicit shopping action and speaker-note share/unshare rules derived from
development evidence. Independently authored examples validate these cases;
contracts, corpus, scorer, interpreter, model settings and controls stay fixed.
One frozen original-corpus regression passes synthetic gates (59/60, held-out
11/12, all dates/privacy). Retain the remaining memory failure and development
answer-shape failure. This qualifies for the already authorized bounded Nano
smoke; subscription timing cannot establish hosted latency or ZDR.
